# Backend dependencies (WS-E.9)

Three files, three jobs:

| File | Purpose | Installed into the runtime image? |
|---|---|---|
| `talent-os/backend/requirements.txt` | Human-edited source of truth — version *ranges*. Edit this when adding/upgrading a dependency. | No (not directly) |
| `talent-os/backend/requirements.lock` | Exact pinned versions resolved from `requirements.txt`, generated by `pip freeze` in a clean venv. `talent-os/Dockerfile` installs from this file. | Yes |
| `talent-os/backend/requirements-dev.txt` | CI/local-only tooling (currently just `pip-audit`). Never installed into the image. | No |

## Regenerating `requirements.lock`

After changing `requirements.txt`:

```bash
cd talent-os/backend
python3 -m venv /tmp/lockvenv
/tmp/lockvenv/bin/pip install --upgrade pip
/tmp/lockvenv/bin/pip install -r requirements.txt
/tmp/lockvenv/bin/pip freeze > requirements.lock
rm -rf /tmp/lockvenv
```

Commit the regenerated `requirements.lock` in the same PR as the
`requirements.txt` change. `pip-compile` (from `pip-tools`) is an equivalent
alternative if you have it installed — either tool just needs to produce a
flat, exact-pinned `pip freeze`-style file.

## Vulnerability scanning

CI runs `pip-audit -r talent-os/backend/requirements.txt` on every push/PR
(`.github/workflows/ci.yml`, job `pip-audit`) and fails the build on a known
vulnerability. A finding that is a false positive or genuinely unfixable
right now goes in `talent-os/backend/.pip-audit-ignore` (one advisory ID per
line, with a comment explaining why) — see that file's header for the exact
format. Don't add an ignore entry without a comment saying why it's safe to
skip and when to revisit it.

## 2026-09 dependency cleanup (WS-E.9)

- `passlib[bcrypt]` removed — dead dependency, nothing imports `passlib`
  (`core/security.py` hashes directly with `bcrypt`, see its "direct
  bcrypt, no passlib" comment). `bcrypt` is now a direct dependency instead
  of riding in via `passlib[bcrypt]`.
- `python-jose[cryptography]` bumped to `>=3.4.0` (CVE-2024-33663 algorithm
  confusion, CVE-2024-33664 DoS via crafted JWE).
- `python-multipart` bumped to `>=0.0.18` (CVE-2024-53981 ReDoS on
  malformed multipart boundaries).
- `sentry-sdk[fastapi]` added, pinned to `2.19.2` — see the Sentry section
  of `talent-os/.env.example` and `core/config.py` (`SENTRY_DSN`). Inert
  (no-op) until an operator sets `SENTRY_DSN`.
